# 浏览器直传助手（lit-uploader.user.js）

把「你已登录机构订阅的浏览器」和「本地文献库」接起来：打开出版商页面时自动识别 DOI/arXiv，匹配库内条目，抓取 PDF 直接传进系统——**不经过浏览器下载文件夹，不需要你点任何下载按钮**。

## 一、安装（一次，约 2 分钟）

1. 浏览器装 **Tampermonkey**（Edge / Chrome 的扩展商店里都有，免费）。
2. 点击 Tampermonkey 图标 → 「添加新脚本」→ **全选删掉模板**，把 `lit-uploader.user.js` 的全部内容粘贴进去 → `Ctrl+S` 保存。
3. Tampermonkey 第一次运行会询问「是否允许访问 127.0.0.1」→ 允许（这是往本地文献库传文件的必要权限）。

## 二、使用前提

- **本地服务在跑**：`cd 03-code && npm start`（脚本上传失败最常见的原因就是服务没开）。
- 浏览器里**保持机构登录态**（如同济图书馆通过 Cambridge / Springer 的认证）。
- 打开任何出版商文章页，右下角出现绿色提示「已入库 1.19《…》」即成功；之后在系统里该条目状态变为「已下载」。

## 三、它的工作方式（供判断可信度）

1. 读页面里的 `citation_doi` 等 meta 标签（或 arXiv 编号），调本地服务 `GET /api/works/lookup` 做**精确匹配**——库里没有的文献它什么都不做，不会乱传。
2. 找 PDF 链接的优先级：`citation_pdf_url` meta → 站点专属规则（Cambridge / ScienceDirect / IEEE / T&F / SAGE / OUP / ACM）→ 页面泛化兜底。
3. 用你当前浏览器的登录会话抓取 PDF，先验三件事才上传：**`%PDF-` 魔数 + 体积 ≥ 8KB + HTTP 200**（出版商返回 HTML 错误页时 HTTP 常常是 200，所以魔数校验不能省）。
4. 以裸 `application/pdf` 请求体 `POST /api/works/:no/asset`，服务端生成规范文件名、做路径校验、验页数，然后落盘为 `<编号>__<slug>.pdf`。
5. 同一条目已有 PDF → 服务端 409，脚本静默跳过（不会重复传、不会覆盖）。

## 三·五、人机验证（CAPTCHA / Cloudflare / WAF）

访问出版商页面或抓 PDF 时如果撞上验证，脚本**不会尝试绕过**，而是：

1. 检测三类信号：HTTP `403 / 429 / 503`、响应体是 HTML 而非 PDF、正文/标题命中验证特征词（captcha / recaptcha / turnstile / just a moment / 人机验证 / 安全验证 …）。
2. 右下角弹出黄条：**「需要你手动完成人机验证」**，并说明还剩几次重试。
3. 你自己在页面上点掉验证；脚本每 **10 秒**自动重试一次，最多 **18 次（3 分钟）**。
4. 验证通过后页面结构可能变，重试时会**重新发现一次 PDF 链接**再抓。

超过 18 次仍不通过 → 本页标记为「失败」（手动模式下不会跳走，你可以点掉验证后用菜单「立即重试本页」再试）。
菜单里的「诊断本页」会额外输出一行 `验证页: 是/否`，用于确认是不是被验证拦住了。

> 被拦的通常是 Cloudflare 的 JS 挑战。因为脚本优先用**页面自身的 fetch（带完整浏览器上下文）**，你在页面上手动过一次之后，`cf_clearance` cookie 生效，后续重试就能通过。

## 三·六、手动模式：你自己开页面，脚本自动直传（v1.2.0 起）

> v1.2.0 **移除了批量队列的自动跳转**。原因：脚本只能在它 `@match` 到的出版商/arXiv/doi.org 域名上运行，自动跳到未覆盖的站点（fipa.org、anthropic.com、github.io 等）后脚本就不再运行，既抓不到东西又会卡住；而机构权限、人机验证这些本来也更适合人来判断。所以改成**你负责打开页面，脚本只负责在你打开的这一页上干活**。

### 怎么用（就三步）

1. 在系统总览页（`http://127.0.0.1:7317/`）工具栏点 **「打开下一篇待采集」** → 新标签打开一条待采集文献的原文页（出版商原链 → DOI → arXiv，会自动跳过既无链接也无 DOI 的条目，如纯专著）。
   也可以直接在列表里点某条的 **「原文」** 链接，或自己从别处进到该文献页面——**只要页面是你自己打开的，脚本都会自动处理**。
2. 在打开的页面上，脚本自动完成「识别 DOI/arXiv → 匹配库内条目 → 找 PDF → 抓取 → 直传」，右下角弹提示告诉你结果。
3. 传完关掉这个标签，回总览页再点一次「打开下一篇待采集」即可处理下一条。

脚本**不会**自动跳到下一篇、也不会批量跑，所以不存在"卡在某个页面"的问题。

### 结果提示（右下角）

| 提示 | 含义 |
|---|---|
| 已入库 `<编号>` | 抓到 PDF 并直传成功 |
| 已在库中 | 本地早就有 PDF，跳过（想重传用菜单「立即重试本页」） |
| 跳过 `<编号>`：需购买/机构无权限 | 页面提示需单独购买（`noaccess`） |
| 跳过 `<编号>`：没找到 PDF 链接 | 站点布局特殊，脚本没找到 PDF（`nopdf`） |
| 页面被拦截/封锁 | 命中 Cloudflare 硬封锁（"Sorry, you have been blocked" 等），换其它来源 |
| 需要你手动完成人机验证 | 你点掉验证，脚本每 10 秒自动重试 |

脚本只匹配**库里已有的条目**（按 DOI/arXiv 命中），不是通用爬虫；本地已有 PDF 的会直接跳过，不会重复上传。

### 网页上的两个入口

- **「打开下一篇待采集」**：一次只开**一个**新标签（你点一次开一个），不会连锁跳转。
- **「脚本说明」**：展开说明卡，含待采集条数、一键装/更新脚本的链接、完整操作步骤。
- 工具栏右侧会显示 **「直传脚本已就绪 v1.2.0」** 或 **「未安装直传脚本」**——这是脚本是否在此页面生效的真实信号。

> ⚠️ v1.2.0 改动较大（删除队列、只保留单页直传），**请重新安装 / 更新一次脚本**：点「脚本说明」→ 卡片里点「打开 lit-uploader.user.js」重装。

### 确认脚本真的注入到了系统页（最重要的一步）

页面右侧如果一直显示「未安装直传脚本」，说明 Tampermonkey 没在这个页面跑起来。按这个顺序排查：

1. **用真实浏览器打开**，不要用 WorkBuddy 的内置预览窗——预览窗里没有 Tampermonkey 扩展，脚本永远注入不了，按钮也不可能变蓝。请在 Chrome / Edge 地址栏直接输入 `http://127.0.0.1:7317/`。
2. 打开系统页后，按 F12 → Console，输入 `window.__litUploader` 然后回车：
   - 返回 `"1.2.0"` 之类的版本号 → 脚本已就绪，工具栏会显示「直传脚本已就绪 v1.2.0」。
   - 返回 `undefined` → 脚本没注入。继续看第 3 步。
3. 重装脚本（确保 @match 含本地地址）：Tampermonkey 仪表盘里**删除**已有的「文献库直传助手」，再打开 `http://127.0.0.1:7317/lit-uploader.user.js` 重新「安装」。只点「更新」有时不会刷新 `@match` 列表，整条删除再装最稳。
4. 确认 Tampermonkey 里该脚本是「已启用」，且脚本详情的"作用于"里包含 `127.0.0.1:7317` 和你要抓的出版商域名。
5. 回到系统页 **Ctrl+F5 硬刷新**，等 2 秒看按钮是否变蓝、状态是否变「直传脚本已就绪」。



## 四、内置的限制（有意为之，不建议改小）

| 限制 | 值 | 原因 |
|---|---|---|
| 两次上传最小间隔 | 15 秒（仅在上传成功后计入；跳过不计时） | 批量抓取在多数出版商条款里被禁止，间隔太短会触发学校/出版商风控 |
| 每日上限 | 60 篇 | 同上 |
| 只匹配库内条目 | — | 它不是通用爬虫，只服务于清单里的文献 |

菜单里有「**立即重试本页**」（忽略已上传标记重跑本页）和「**诊断本页**」（输出本页识别到的 DOI/arXiv、是否命中库、找到的 PDF 链接、是否为验证页）两个入口，用于限速/断网失败后补跑与排错。用法见「三·六」。

## 五、常见问题

- **右下角没反应**：多半是页面上没有 `citation_doi` 也没有 arXiv 编号（比如 IEEE 有些页面）。按 F12 看 console（把脚本顶部 `DEBUG` 改为 `true` 可看详细日志）。
- **「匹配到 X 但没找到 PDF 链接」**：该站布局特殊。把文章页的 HTML 结构告诉我（或截图），我在 `SITE_RULES` 里加一条规则即可。
- **「已匹配但暂缓上传（限速中）」**：不是失败，等 15 秒刷新页面或用菜单里的「立即重试本页」。
- **页面没反应 / 没弹提示**：先确认脚本真的注入了（见「确认脚本真的注入」），再看页面是否在本脚本覆盖的域名里（`@match` 只含那批出版商/arXiv/doi.org；fipa.org、anthropic.com、github.io 这类**不在**覆盖范围内，脚本不会在那里运行，属正常）。可用菜单「诊断本页」看它识别到了什么。
- **页面显示 Cloudflare "Sorry, you have been blocked"**：属于硬封锁，脚本会弹「页面被拦截/封锁」并跳过本篇，请换其它来源（或换网络/稍后再试）。若是机构没权限（如 ScienceDirect "not subscribed"），会提示「需购买/机构无权限」。
- **同一篇想重传**：Tampermonkey 菜单 → 「立即重试本页」（会清掉本页的已上传标记）。
- **换电脑 / 换端口**：改脚本顶部的 `API` 常量。

## 六、与系统其它部分的关系

- arXiv 的 321 条仍然走系统自动下载（`npm start` 后在网页上点下载），**不需要**这个脚本；这个脚本只服务「仅有 DOI / 需人工」的那 64 条。
- 上传成功后系统会**自动**走抽取 → 可翻译 → 可对话的后续链路，无需额外操作。

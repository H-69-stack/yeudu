# 翻译插件：从线性段落流改成按原文版式还原的对照页

> 目标（用户原话）："我希望是第 1、2 张图片里面的那种，但是现在却是第三种那种"——即右侧译文要保留论文的版面（页眉、居中标题、双栏、图注在图下、脚注在页脚、插图在原位），而不是一条"第 N 页 + 原文小字 + 译文"的线性流。
>
> 完成日期：2026-11-04 · 三个子代理并行（前端渲染 / 服务端版面数据 / 译文质量），我本人做集成与验收。

## 1. 一句话结论

右侧译文现在是**一张按原文坐标排版的纸**：每页一个 `.page-sheet`，每个段落绝对定位在它原来的 bbox 位置，字号按行高比例缩放，图区把 PDF 原图直接贴回版面，默认「仅译文」，可切「对照」。左右两栏滚动对齐，点段落可回跳左侧 PDF 同一位置。

### 2.2 译文质量（服务端，新增 `quality.js`）

- **送翻白名单**：`figure-label / header / footer / page-number / equation / reference`、`is_math=1`、`is_label=1` 一律不送（省 token，也不再产生"图内标签被翻成句子"）；**图注单独成批**并附 `CAPTION_INSTRUCTION`。
- **乱码兜底**：`minCjkRatio=0.15`、`LATIN_GARBAGE`（≥2 个 ≥5 位大写串且 CJK<0.35）、`echoMinLatinLetters=40`（整段英文回传）；坏段用 `temperature=0.1` 严格重试，二次仍坏则 `dst=null` + warn，**不写缓存**。
- **段数对齐**：`alignBatchOutput` 防止模型少返/多返导致译文串段；`preview` 接口返回 `quality` 指标。
- **只读巡检**：`03-code/server/cli/lint-translations.js`（318 行）——不写库，列出不合格译文。

基线（生产库，只读）：3532 条译文里 CJK<15% 563 条、拉丁垃圾 13 条、整段英文 19 条。

### 2.3 前端渲染（`page-layout.js` 新增 584 行）

- `pageSizeOf()`：页尺寸优先用 API 返回的真实 `width/height`，其次 viewer，再次 `aspect`，最后 A4 —— 之前写死 `1/1.294` 会让 2.6（430×660）、2.3（454×679）、1.19（559×842）偏 13–16%。
- `SheetPage`：绝对定位 + 重叠下推 + 纸高自适应（`.grown`）。
- `columnPlan` / `rowInfo`：单行段（标题、作者行、节标题）宽度不足列宽时补到列宽，否则中文换行把标题挤成两行。
- 图区：`figuresOf` / `insideFigure` + `viewer.renderRegion()` 把 PDF 原图贴进 canvas。
- `translate.js` 重写为 `layout`（默认）/ `flow` 双模式；`setMode` 只切 class 不重建 DOM，避免滚动跳动。

我在 `03-code/web/assets/viewer.js` 补了两个方法：`pageSizePt(pageNo)`（真实 PDF 点尺寸，含 rotate）与 `renderRegion(pageNo, box, canvas, {scale})`（用 `transform` 把指定区域画进调用方 canvas）。

## 4. 已知限制（都是实测出来的，不是猜的）

1. **PDF 里用矢量字形画的文字抽不到**。1.11 第 1 页的作者行 `RODNEY A. BROOKS, MEMBER, IEEE` 在 PDF 文本项里根本不存在（我 dump 了 y∈(630,745)，只有 5 条标题文本项），所以它既不会被翻译，又会作为图区 canvas 的一部分露在译文中。同一类问题就是参考图里也有的 `EVRNKSHUHO HGUVVJGF` 这类垃圾串——那是字体缺 ToUnicode 映射。**没有盲裁图框**（会切掉真实图形）。
2. **中文比英文短/长都会让纸变高**：段落高度用实测文本流高度，纸按内容下延（`.grown`），因此同页左右两栏高度不完全等于原 PDF 页高。
3. **字号按页宽估算**（`bodyFontPt = pageW / 52`），不是精确的 PDF 字号；A−/A+ 会整体缩放。
4. **旋转页/横排表**未特殊处理。
5. **图区依赖左侧 PDF**：`layout-preview.html` 不加载 PDF，所以只能画虚线占位。

## 5. 升级影响（必须知道的两条）

1. `EXTRACTOR_VERSION` 4→5 且 `prompt_fp` 由 `1e30293e` 变为 `e2543ebb` ⇒ **库里 3532 条旧译文全部不再命中**。重启后打开阅读页会显示「已译 0」，需要点一次「全文翻译」。
2. `03-code/web/assets/reader.js:154-171`：打开文档时若 `storedV !== currentV` 会**自动强制重抽**（免费，单篇约 1 秒），重排后**只有该文档"在当前指纹下已有译文"时才会自动接着译**（`hadTranslation`）。由于指纹从 `1e30293e` 变成 `e2543ebb`，库里 3532 条旧译文都不再命中，`hadTranslation` 为 false ⇒ **这次不会自动扣费**，页面显示「已译 0」，需要手动点「全文翻译」。这一点在沙箱里实测过（首次打开 1.11 时就是「已译 0」，没有自动发请求）。

## 7. 成本

沙箱只翻了 1.11 第 1 页（17 段 / 4 次请求），约 3–4k tokens。全库 4865 个可译段按此单价估算约 80–120 万 tokens——远超前几次会话的估算，原因是 v5 把 `caption` 与部分 `figure-label` 纳入送翻、且段更碎。建议先只翻 1–2 篇验证效果，再决定是否全量重翻。

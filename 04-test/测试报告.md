## 13. 问题清单（按严重度）

### D1【缺陷】"浏览器缺失时 skip"只对一半用例生效，与文档/注释承诺不一致

- **复现步骤**
  ```
  $ mkdir -p .tmp/verify/empty-browsers
  $ env -u NODE_OPTIONS PLAYWRIGHT_BROWSERS_PATH="$PWD/.tmp/verify/empty-browsers" \
      TEMP="$PWD/.tmp/temp" TMP="$PWD/.tmp/temp" node --import tsx --test tests/page-image.test.ts
  ℹ tests 23   ℹ pass 16   ℹ fail 2   ℹ skipped 5      # 退出码 1
  ✖ pdfjsAssetDir 归一化：包根与 build 目录两种写法等价，且资源面非空
    Error: lit_page_image 启动失败：Chromium 可执行文件不存在（期望 …\empty-browsers\chromium-1228\chrome-win64\chrome.exe）…
  ```
- **根因（可复现的证据链）**：`tests/page-image.test.ts:353` 的 `isEnvironmentFailure()` 用正则
  `/启动 Chromium 失败|EPERM|Executable doesn't exist|ENOENT.*chrome/`，
  而实现抛出的消息是中文「**Chromium 可执行文件不存在**」→ 不匹配 ⇒ 不 skip。走 `getRenderer()` 的 5 个用例被正确 skip，直接 `new PageImageRenderer()` 的 2 个用例则失败。
- **影响**：README「浏览器/样本缺失时 skip 不 fail」与测试文件头注释不成立；换机/CI 上 `gate.sh` 会红。**注意方向**：红比"静默 skip"安全，所以我把它定为缺陷而非阻断；但它属于"文档声称了但没实现"，按任务清单第 8 项必须报出。
- **建议**（只报不改）：`isEnvironmentFailure` 增加 `/Chromium 可执行文件不存在|pdf\.js|playwright/u`；或把那 2 个用例改成走 `getRenderer()`。

### R1【建议】设计 v3 与实现存在 3 处偏差，权威文档未同步

### R2【建议】`pxPerCell.srcPxPerCell` 是恒真式，R-P3-7③ 的信息量为零

```ts
srcPxPerCell: round(TOKEN_CELL_PX * Math.sqrt(areaFraction), 2)   // full→42, quad→21，数学上必然成立
```
设计 §16 R-P3-7 把它当"定量断言"，但它与 `plan.scale`、与真实输出像素**无关**——即使 `planRender` 写错（例如象限不放大），这条断言仍然过。因此"三条定量断言全过"实际只有 ①（scale 比）④（尺寸）有效。
- **建议**：改成用 `plan.scale` 与 `plan.width/height` 推导（例如 `srcPxPerCell = TOKEN_CELL_PX * (vp1 面积)^0.5 / (输出长边… )`），或直接删掉该字段别当断言。

### O1【观察】真实 dsh 路径默认失败：TEMP 必须可写，但 README 的 L4 复现命令没提

我第一次按 README 原样跑 L4（不设 TEMP）时，工具**响亮失败**、模型**拒绝编造**：

这条**同时是两条设计的正面证据**（§18-2 故障不伪装成业务空值 + persona「未查看必须显式说明」），也说明实现没有把环境故障洗成"这页没内容"。
但 README「已验证的能力」里的 L4 命令（`dsh --json "用 lit_page_image 看 1.17 第 1 页…"`）**没有**带 `TEMP=.tmp/temp`，照抄会得到失败；建议补一句（`gate.sh`/探针都自己兜了 TEMP，CLI 路径没有）。

### O2【观察】`no_pdf` 在成本闸之前返回 ⇒ 对不存在编号的调用不受配额约束

`execute` 顺序是 `assetPath===null → return no_pdf`，然后才 `assertCallBudget`。因此一个模型可以对不存在的编号无限次调用（每次 0 图 0 token，不算钱，但会烧上下文与轮次）。设计 §18-5 的"成本闸"目标是 token，不受影响；但"防打转"这一栏可考虑把这类调用也纳入同参打断。低风险。

### O3【观察】设计 §1 成功标准①「输出长边 1500」在 A4 竖版以外的页面上不成立

1.17（570×759 pt）实际输出 1113×**1482**，4.4 输出 1118×**1475** —— 是 `maxPixels=1_650_000` 先到顶（面积约束），`maxEdge` 未成约束。几何行为正确（这是我 A5 断言的一部分），但"长边 1500"这句应改成"≤1500"。仅文档措辞问题。

## 16. 结论

**建议放行。**

依据：契约完整性、成本闸方向、出网阻断、裁剪语义、seam 干净度、persona 落点、确定性 7 项核心断言全部由**我自己的命令**独立复现（72 条断言全绿，含 2 次真实 L4 会话），设计 §18 的 7 条反例中 4 条（2/3/4/7）有正面实证，1 条（5）由成本闸覆盖，1 条（6）部分覆盖。

**放行前提（建议，均不影响"能用"）**
1. **必改（低成本）**：修 D1 的 `isEnvironmentFailure` 正则（或让那 2 个用例走 `getRenderer()`），使"缺浏览器 ⇒ skip"的承诺成立；否则请把 README/测试注释改成"缺浏览器会 fail"。

4. **建议**：README 的 L4 命令补 `TEMP=.tmp/temp`（本机默认 TEMP 不可写，照抄会失败）。
5. **建议**：把 U1（`page.on('crash')`）与 U4（附件 id 复现性）排进下一轮验证；如果崩溃自愈是本特性的卖点，别只留代码路径不验证。
